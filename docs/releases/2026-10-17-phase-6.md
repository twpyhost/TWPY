## Behavior

Admin-only `/admin/archivo` creates plain-text recaps, draft/save/publish/retract, permanent slugs after first publication, season/date, optional tournament association, HTTPS VOD links, photo captions/credits and ordering. `/archivo` filters published entries by season; details link to tournament results and result pages link back to published recaps. Deleted tournaments leave the recap intact. Event association awaits Phase 2.

Pages and sitemap read current publication state without a server cache. Proxy checks produce real 404s for missing/draft slugs before streaming. Media URLs expire after 900 seconds; retraction blocks new signatures, while existing URLs may work for their remaining lifetime. A visitor's already downloaded page/photo cannot be recalled. The editor explains this limit. VODs are ordinary safe HTTPS links with an unavailable-provider explanation.

Private bucket `archive-media`: decoded JPEG/PNG/WebP only, maximum input and processed file size 2 MiB, maximum 20 million pixels, no animated/multipage images. Re-encoding removes metadata/trailing content. Server-generated immutable paths and serialized reservations enforce a 100 MiB aggregate ceiling, including pending/deleted files until physical cleanup succeeds. Publication and credit edits lock the parent entry. Anonymous and Liga users cannot upload, reserve, list drafts or mint arbitrary Storage signatures. Internal RPCs are service-only, invoker functions with fixed search paths.

## Backup and restore

The media workflow runs weekly and on demand, retains artifacts for 14 days, and serializes runs. Each run holds a repeatable-read exported snapshot; `pg_dump --snapshot` and metadata use that same snapshot/run ID. Files use immutable paths. A 30-minute lease blocks physical cleanup while the 15-minute job collects referenced ready assets; entry edits/uploads can continue. Failed/expired leases release cleanup on subsequent media activity. The job downloads bytes, verifies SHA-256/size/entry/asset associations, archives the directory and encrypts it. No plaintext bundle is uploaded and no copy is stored in the primary Storage project.

Save the paired artifact outside GitHub if longer media retention is needed. A 90-day DB-only dump cannot promise old photos beyond the paired media window. Restore **the DB and metadata from the same media artifact**, never a newer independent DB dump with older media.

1. In a private temporary directory, download `archive-<run>-<attempt>` and decrypt with the offline key:

   ```text
   node scripts/backupCrypto.js decrypt archive.tar.gz.enc archive.tar.gz
   ```

   `BACKUP_ENCRYPTION_KEY` must be set in the process environment. Decryption rejects modified/truncated files and deletes partial output. Extract the authenticated tar into a new empty private directory. Run:

   ```text
   node scripts/backup-archive-media.js verify EXTRACTED_DIRECTORY
   ```

   Abort on any missing/corrupt file or mismatched association/run ID. `manifest.json` includes paired DB/metadata hashes and object path, bytes, SHA-256, entry and asset IDs.
2. Initialize an **isolated** Supabase-compatible database with the committed migrations/platform schemas. Restore Auth identities separately or supply temporary identity stubs for a rehearsal; the public dump contains FKs to `auth.users`. Decompress `database.sql.gz` and restore with `psql -v ON_ERROR_STOP=1`. Preserve object GRANT/REVOKE statements. In a project-user rehearsal, omit only `ALTER DEFAULT PRIVILEGES FOR ROLE supabase_admin` statements from a restore copy; keep the original artifact untouched.
3. Create a private `archive-media` bucket with the migration's MIME/size restrictions. Upload each `objects/<storagePath>` file through the Storage API at its manifest `storagePath`, with replacement disabled. For a rehearsal use a separate temporary bucket instead; never overwrite the live project. Check hashes of downloaded restored bytes and compare every ready DB asset to the matching manifest asset/entry/caption/credit. Do not insert Storage catalog rows by SQL.
4. In the restored database clear `archive_media_state.backup_run_id`/`backup_expires_at`. The dump intentionally contains the backup lease. Non-ready reservations/deleted/deleting rows may refer to files outside the ready-object manifest; retire/clean these through the normal cleanup path before reopening uploads. Verify public published pages, draft denial and service-only RPC privileges before switching traffic. Remove temporary plaintext, DB and bucket after the rehearsal.

The standalone collector is `node scripts/backup-archive-media.js backup NEW_DIRECTORY`; use only explicit target credentials. It uses PostgreSQL 17 tools in Docker and accepts `ARCHIVE_PG_CONTAINER` for a known local container. Do not source a production `.env.local` while running tests.
